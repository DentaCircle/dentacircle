# Roadmap

Keep the plan honest and small.

## When to use

- A milestone just finished and the next phase needs a fresh look.
- Slices keep coming out too big or too small.
- A feature was cut, added, or reordered.
- The developer asks where things stand or what is left.

## How

1. Read PRODUCT.md, ROADMAP.md, `.shipit/open.md`, and the done briefs.
2. Say where the project is: milestone, ticked slices, actual versus expected time.
3. Propose the change with a reason. Keep every milestone demoable.
   Prefer cutting or splitting over adding.
4. Move work from later phases only when an earlier slice truly needs it.
5. Check any change to scope against the non-goals in PRODUCT.md. If it crosses one, ask.
6. Apply the edit after the developer agrees. Update PRODUCT.md if scope or decisions changed.

Do not rewrite finished slices. Do not add slices for work nobody asked for.

Use plain words and short instructions.
