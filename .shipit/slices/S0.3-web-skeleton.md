# S0.3 Web skeleton

Status: built
Branch: slice/S0.3-web-skeleton
Size: M

## Goal

Someone can run the web app with one command, see a responsive app shell with navigation, open a status page that shows live API and database health through a typed API client, and write component tests with a ready harness.

## Acceptance criteria

1. **Run.** `make web-dev` starts Next.js on port 3000. `/` renders inside the shell.
2. **Shell.** Header with app name, sidebar navigation, and a `main` landmark. Links come from one typed config. Only routes that exist are listed (Dashboard `/`, Status `/status`). The active link has `aria-current="page"`.
3. **Responsive nav.** Below the `md` breakpoint the sidebar is replaced by a menu button that opens and closes a sheet. The button has an accessible name and the sheet closes on link click.
4. **Dashboard placeholder.** `/` shows an empty state ("nothing to show yet"). No fake or patient-like data.
5. **Status page.** `/status` shows API and database state from `/health` and `/health/ready`. Three states: ok, database not ready (API answered 503 in the standard error shape), API unreachable. Error states show the error code and `request_id`, never the raw response body or exception text.
6. **Typed client.** `getHealth` and `getReadiness` return a result type, `{ ok: true, data } | { ok: false, error }`, and never throw on HTTP errors. Error kinds: `api` (parsed error shape), `network`, `timeout` (5 s). A non-JSON or malformed error body falls back to a generic message.
7. **Types come from the API.** `make api-types` exports the OpenAPI schema and regenerates `schema.d.ts`. An API test fails if the committed `openapi.json` differs from `app.openapi()`. The client imports its response types from the generated file, so `tsc` fails if a route changes shape.
8. **Error, loading, not-found.** `app/error.tsx`, `app/not-found.tsx`, and a `loading.tsx` for `/status`. The error boundary shows fixed text and never `error.message`.
9. **Test harness.** Vitest runs `.tsx` component tests with jsdom and React Testing Library. The S0.1 placeholder test and file are removed.
10. **Commands and CI.** `make check` passes. CI web job also runs `pnpm build`. README and `.env.example` gain the web steps and `API_BASE_URL`.

## Changes

- Data: none. No migrations. No `clinic_id` (nothing is clinic-owned).
- API: no new routes, no behavior change. Adds `apps/api/scripts/export_openapi.py` (sets a placeholder `DATABASE_URL` if unset; creating the app makes no connection), the committed `apps/api/openapi.json`, and `tests/test_openapi_snapshot.py`.
- UI, layout at `apps/web/` root, matching AGENTS.md (`tsconfig` and Vitest globs move from `src/` to the new folders):
  - `app/` (`layout.tsx`, `page.tsx`, `status/page.tsx`, `status/loading.tsx`, `error.tsx`, `not-found.tsx`, `globals.css`)
  - `components/` (`app-shell`, `main-nav`, `mobile-nav`) and `components/ui/` (shadcn: `button`, `sheet`, `badge`, `card` only)
  - `features/status/` (status card and its states)
  - `lib/api/` (`client.ts`, `errors.ts`, generated `schema.d.ts`), `lib/utils.ts`
  - Config: `next.config.ts`, `postcss.config.mjs`, `components.json`, `eslint.config.js`, `tsconfig.json`, `vitest.config.ts`, `vitest.setup.ts`
- Server components call the API directly using the server-only `API_BASE_URL` (default `http://127.0.0.1:8000`). No `NEXT_PUBLIC_` variables, so the API address is not shipped to the browser.
- Makefile: `web-dev`, `web-build`, `api-types`. Updated: `README.md`, `.env.example`, `.github/workflows/ci.yml`, `package.json`, `pnpm-lock.yaml`.

## Out of scope

- Login, sessions, auth, role-based nav (S0.4, S7.1). No CORS and no `/api` proxy: the browser does not call the API yet. S0.4 picks CORS or a Next rewrite when cookie sessions need it.
- Nav items for modules that do not exist yet. Dark mode toggle. Persistent search.
- Data fetching or state libraries (TanStack Query, Zustand), Zod, forms, charts.
- End-to-end browser tests (Playwright). Dockerfile or deployment for the web app (S0.5).
- Declaring the error shape in OpenAPI. The client defines it by hand to match S0.2.

## Decisions and risks

New dependencies need your approval (AGENTS.md stop). Proposed list:

- Runtime: `next`, `react`, `react-dom`, `tailwindcss`, `@tailwindcss/postcss`, plus the shadcn set: `radix-ui`, `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react`, `tw-animate-css`.
- Dev: `@types/react`, `@types/react-dom`, `@types/node`, `eslint-config-next` (or `@next/eslint-plugin-next`), `@vitejs/plugin-react`, `jsdom`, `@testing-library/react`, `@testing-library/jest-dom`, `@testing-library/user-event`, `openapi-typescript`.
- The shadcn CLI is run once with `pnpm dlx` and is not a dependency. It copies component source into the repo, so you review it as ordinary code. In the review packet I will mark generated files separately from ours.

Your decisions, to be recorded in PRODUCT.md on approval:

- **UI system: Tailwind plus shadcn/Radix.** Tradeoff: more files to review now and more code you did not write, in return for accessible dialogs, selects and tables from S1.1 on. This slice adds only `button`, `sheet`, `badge` and `card`, the ones it actually uses.
- **Typed client: `openapi-typescript`** from a committed `openapi.json`. Tradeoff: one more dev dependency and a generate step, in return for types that cannot drift silently (criterion 7).

Choices where I recommend one option:

- **Server-side calls only.** Keeps CORS and cookie handling out of this slice. Cost: S0.4 must choose between CORS and a proxy, so this is an input to the auth decision.
- **Root layout, not `src/`.** AGENTS.md says `apps/web/features/`. This moves the S0.1 globs. Tradeoff: a small config change now instead of a doc change.
- **ESLint 10 risk.** S0.1 uses ESLint 10 flat config. `eslint-config-next` may not support it yet. Fallback: keep `typescript-eslint` and add only `@next/eslint-plugin-next`. If neither works, stop and ask rather than downgrade ESLint.
- **pnpm build scripts.** Next, Tailwind and sharp may need entries in `pnpm.onlyBuiltDependencies`. Each one added will be listed with why.
- **Next.js version.** Current stable at build time, pinned by the lockfile. Node 22 or newer is already required, CI uses 24.
- **Size.** This is close to the upper limit of one review. If the shadcn setup swells the diff, the typed client is split into its own slice.
- **Docker.** Not needed for web tests. The live status click-through needs PostgreSQL and the API running. If Docker is still missing, the review packet will say exactly what was not run.
- **Branch base.** S0.2 CI is still unconfirmed and S0.2 is not merged. The repo is on `slice/S0.2-api-skeleton`. Confirm CI is green, merge S0.2 to `main`, then branch `slice/S0.3-web-skeleton` from `main`. S0.3 needs the committed OpenAPI file from the API, so it should not stack on an unreviewed branch.

### Decisions made

- `eslint-config-next` crashes on ESLint 10 (`react/display-name` calls a removed API). Used `@next/eslint-plugin-next` instead. ESLint was not downgraded.
- `@vitejs/plugin-react` is 5.2. Version 6 needs Vite 8. Vitest 3 uses Vite 7.
- The CLI also installed `shadcn` and `cn`. Those are not in the approved list, and `shadcn` is the CLI (Babel, MCP). They are not dependencies. `cn` is a local function. The sheet's open and closed variants are copied into `globals.css`.
- No new `pnpm.onlyBuiltDependencies` entries. `esbuild` was already there. pnpm warned that its build script was ignored. Vitest still ran.
- Next.js 16.3.8 and React 19. The CLI added the Geist font. It is not used, so the build does not download a font.
- `agentRules: false` so `next dev` does not write `apps/web/AGENTS.md`.
- `/status` is `force-dynamic`, so `pnpm build` does not call the API.
- An API error includes the HTTP status so a 503 can be shown as "database not ready". A malformed body uses code `invalid_response` and an empty request id, and the card hides that empty id.

### Unsure points

- In the Cursor browser, Next reported a hydration mismatch. The server log diff is only `data-cursor-ref`, which the browser tool adds. I did not see a mismatch in our markup.
- `globals.css` includes the generated `.dark` tokens. There is no dark-mode toggle. Later shadcn components may need more variants than `data-open` and `data-closed`.

### Click-through

1. `cp .env.example .env` if needed. `make db-up`, `make migrate`, `make api-dev`, `make web-dev`.
2. Open `http://localhost:3000/` (not `127.0.0.1`: Next blocks dev scripts from that host). The shell shows Dentacircle, Dashboard, Status, and "nothing to show yet".
3. Open `/status`. With Postgres and the API up, it says the API and database are ready.
4. Narrow the window below the `md` breakpoint. The sidebar hides, "Open menu" shows, the sheet opens, and choosing a link closes it and changes the page.
5. `docker compose stop db`, reload `/status`. It says the database is not ready, with code `service_unavailable` and a request id. `docker compose start db`.
6. Stop the API and reload `/status`. It says "API unreachable."
