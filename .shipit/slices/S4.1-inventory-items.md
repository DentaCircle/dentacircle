# S4.1 Inventory items

Status: approved
Branch: slice/S4.1-inventory-items
Size: L (split point named in decisions; recommended: keep as one, review in pieces)

## Goal

An inventory admin can set up what the clinic stocks: categories, items (gloves, materials, medicines as ordinary items), and for each item its batches with expiry dates. Nobody can yet add or remove stock. That is S4.2.

## Acceptance criteria

### Categories

1. **Create.** `POST /inventory/categories` with `{name}` returns 201. `name` is trimmed, 1 to 80 characters. A name already used in the clinic (ignoring case) is 409 `duplicate_name`.
2. **Rename.** `PATCH /inventory/categories/{id}` with `{name}` follows the same rules and returns 200. The same name as its own current name is allowed and writes no audit row.
3. **List.** `GET /inventory/categories` returns every category of the clinic, sorted by name (case-insensitive), with `item_count`. No paging (a clinic has a handful). No delete.

### Items

4. **Create.** `POST /inventory/items` with `{name, category_id, unit, low_stock_threshold}` returns 201 with status `active`. `name` is trimmed, 1 to 120 characters, unique in the clinic ignoring case (409 `duplicate_name`). `unit` is trimmed, 1 to 30 characters (free text such as "box", "tablets"). `low_stock_threshold` is a whole number from 0 to 1,000,000 (default 0). `category_id` must be a category of this clinic, else 404.
5. **Edit.** `PATCH /inventory/items/{id}` takes any of `name`, `category_id`, `unit`, `low_stock_threshold`. An empty object is 422. Same rules as create. Allowed while inactive.
6. **Status.** `POST /inventory/items/{id}/status` with `{status: active|inactive}` returns 200. Items are never deleted. The same status again is 409 `invalid_status`. An unknown value is 422.
7. **List.** `GET /inventory/items?status&category_id&q&page&page_size` returns `{items, total, page, page_size}`. `status` is `active` (default), `inactive` or `all`. `q` is a case-insensitive "contains" on the name. Sorted by name. Each item has `id`, `name`, `category` (`id`, `name`), `unit`, `low_stock_threshold`, `status`, `batch_count`. An unknown `category_id` returns an empty list, not 404. Paging and 422 rules match `GET /patients/{id}/documents`.
8. **One item.** `GET /inventory/items/{id}` returns the item shape from 7 plus `batches` (see 9 to 12). Another clinic's id is 404.

### Batches and expiry

9. **Add.** `POST /inventory/items/{id}/batches` with `{batch_number, expiry_on?}` returns 201. `batch_number` is trimmed, 1 to 60 characters, unique within the item ignoring case (409 `duplicate_batch`). `expiry_on` is an optional date from 2000-01-01 through 20 years ahead of the clinic-local today. Past dates are allowed because old stock is sometimes entered. A batch holds no quantity in this slice.
10. **Inactive item.** Adding a batch to an inactive item is 409 `item_inactive`. Viewing and editing existing batches still work.
11. **Edit a batch.** `PATCH /inventory/batches/{id}` takes `batch_number` and `expiry_on` (`null` clears it). An empty object is 422. Same rules as 9. No delete.
12. **Batch shape.** `id`, `batch_number`, `expiry_on`, `expired` (calculated: `expiry_on` is before the clinic-local today, never stored), `created_at`. Order in an item: earliest expiry first, no expiry last, then newest created.

### Rules that apply to all routes

13. **Roles.** Write routes (every `POST` and `PATCH`): `inventory_admin`, `clinic_admin`. Read routes (every `GET`): `inventory_admin`, `clinic_admin`, `clinician`. `receptionist` gets 403 everywhere. No session is 401. Order of checks: 401, role, 422, 404, then 409. The route-walk test still passes.
14. **Tenancy.** Every query filters `clinic_id`. Another clinic's category, item or batch is 404 with no hint of which part failed. The same name or batch number in two clinics is fine.
15. **Audit.** Each create writes one audit event (`inventory_category`, `inventory_item`, `inventory_batch`, action `create`, no changed fields). Each edit writes one `update` event listing the changed field names only, and none when nothing changed. A status move writes one `status_change` event with `["status"]`. All in the same transaction as the change. If the audit write fails, no row remains.
16. **No echo.** No error body or log line contains a submitted name, unit, batch number or id. A test checks the 404, 409 and 422 paths.
17. **No stock, no cost, no supplier.** No quantity column exists, no route changes stock, and the schema has no cost or supplier field.

### Migration

18. **Migration `0018`** is additive: three new tables only. Up, down, up works. Constraints: status in (`active`, `inactive`); the length rules above; non-negative threshold; unique `(clinic_id, lower(name))` on categories and on items; unique `(item_id, lower(batch_number))`. Composite foreign keys with `clinic_id`, and unique `(id, clinic_id)` on each table, as in earlier slices.

### Web

19. **Inventory page** `/inventory` (nav item "Inventory"): items table (name, category, unit, threshold, batch count, status badge), a status switch (Active, Inactive, All), a category filter, name search, pagination. "Add item" form (name, category, unit, threshold) with field errors. A small "Categories" panel: list, add, rename. Empty states: "No inventory items yet." and, with no categories, "Add a category first." beside the form. Fixed notices per outcome and fixed text for 409 and 404.
20. **Item page** `/inventory/[id]`: details, edit form, Deactivate or Reactivate (deactivate asks for confirmation), and the batches list with an expired badge. "Add batch" form (batch number, optional expiry date). Inline edit of a batch. Hidden form and fixed text when the item is inactive. Not-found, no-access and error states match the Lab page.
21. **Access in the UI.** Write forms and buttons are hidden for `clinician` (read only). `receptionist` sees "You do not have access." The API still enforces both.

### Proof

22. **Break it once.** The builder removes in turn the clinic scope on the item lookup, the clinic scope on the category check in item create, the unique batch rule, the inactive-item guard on batch create, and the write-role check on one route, sees a test fail each time, restores them, and records it in the review packet.
23. **Visual proof** in `.shipit/proof/S4.1/`.

## Out of scope

- Current stock, restock, transactions, and any way to change a quantity (S4.2).
- Resource rules per procedure and consumption on care session completion (S4.3).
- Low-stock, out-of-stock and expiring-soon alerts and their time windows (S4.4). This slice shows only `expired`.
- Reorder threshold (a second threshold), supplier, purchase cost, and any billing.
- Deleting or deactivating categories or batches, moving an item between clinics, barcodes.
- Dashboard counts (Phase 6), patient or timeline links (inventory is not patient data).
- Receptionist access. Role-based navigation (S7.1).

## Decisions and risks

- **Whole-number quantities (recommended).** Threshold is an integer, and S4.2 will count whole units. The spec's "0.5 unit" example is handled by choosing a smaller unit ("ml", "pieces"). Tradeoff: decimals cost a numeric type, string JSON and rounding rules in every later slice, and are painful to retrofit. If you want decimals, say so now.
- **Batches hold no quantity yet (recommended).** The spec says stock changes only as transactions, so a quantity typed on a batch would be a silent overwrite. Here a batch is a label plus an expiry date. S4.2 adds quantity through restock transactions that point at a batch. Tradeoff: after this slice the screen shows batches but no stock. Alternative: move batches to S4.2 and keep S4.1 to categories and items, which means changing the roadmap line.
- **One threshold, not two.** `low_stock_threshold` is the only level S4.4 needs. The spec's "reorder threshold" can wait.
- **Who reads and writes (recommended).** Write: `inventory_admin`, `clinic_admin`. Read: those two plus `clinician`, who will need stock and expiry for S4.3. `receptionist` has no use for it. Tradeoff: if reception should see stock, adding a role later is one line, but removing it after use is harder.
- **Categories are a table, not free text.** Matches the spec's `InventoryCategory` and keeps names consistent for S4.4 and analytics. No default categories are seeded. S7.3 seeds synthetic data. A fresh clinic starts with none and adds them on the page. Tradeoff: one extra step the first time.
- **Purchase cost and supplier are left out.** PRODUCT.md puts billing and financial analytics out through M5, and the spec lists "Purchase cost" as a field and "Basic financial metrics" in its dashboard phase. Recommendation: keep both out. This will come up again in S4.2 (restock form), so confirm there.
- **Deactivate, never delete,** for items, as for appointment types and patients. Categories and batches have no delete or deactivate yet. Cost: a wrong batch stays on the list (it can be renamed). Fine until S4.2 gives batches a meaning.
- **Audit and names.** Inventory names are not patient data, but the audit table keeps its rule: field names only, never values.
- **Size.** This is L: three tables, about eleven routes, two pages. A natural split is S4.1a (categories and items, criteria 1 to 8, 13 to 17, part of 18 to 21) and S4.1b (batches and expiry, criteria 9 to 12). I recommend keeping one slice and reviewing in the pieces below, because the batch work reuses the same layers and is small. Say if you want the split and I will update ROADMAP.md.
- **Branch base.** Current branch is `slice/S3.3-lab-work` (sealed). Branch from `main` if its PR is merged, otherwise from `slice/S3.3-lab-work`.
- **Open items:** nothing in `.shipit/open.md` blocks this slice.
