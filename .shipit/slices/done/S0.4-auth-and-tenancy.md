# S0.4 Auth and tenancy

Status: done
Branch: slice/S0.4-auth-and-tenancy
Size: M (upper end. See the split option in Decisions and risks)

## Goal

Someone can log in to the API with an email and password, stay logged in with a cookie, log out, and every later route can say which roles may call it and be scoped to the caller's clinic.

## Acceptance criteria

1. **Schema.** `alembic upgrade head` creates `clinic`, `app_user`, `user_role` and `auth_session`. `downgrade` to `0001_baseline` removes them. Upgrade, downgrade, upgrade works. The S0.2 migration test that expects only `alembic_version` is updated to match.
2. **Roles.** `user_role` allows only `clinician`, `receptionist`, `inventory_admin`, `clinic_admin` (database check) and each pair (user, role) once. A user can hold several roles.
3. **Email.** Stored lowercase. Unique across all clinics, ignoring case. A second user with `A@x.test` after `a@x.test` is rejected.
4. **Passwords.** Stored only as an Argon2id hash. No response, error body or log line ever contains a password or hash (tests use a synthetic marker).
5. **Login success.** `POST /auth/login` returns 200 with `{user: {id, email, full_name, roles, clinic: {id, name}}}`. It sets cookie `dc_session`: HttpOnly, SameSite=Lax, Path=/, Max-Age from `SESSION_TTL_HOURS`, Secure when `COOKIE_SECURE=true`. The body has no token. The database stores only a SHA-256 hash of the token.
6. **Login failure.** Unknown email, wrong password and inactive user all return the same 401 `invalid_credentials`. No cookie is set and no session row is created. An unknown email still runs one password verification, so timing does not reveal which emails exist.
7. **Login validation.** A missing or malformed field returns the standard 422 and does not echo the submitted password.
8. **Current user.** `GET /auth/me` returns the same user summary for a valid cookie. No cookie, an unknown token, an expired session, or a user made inactive after login all return 401 `unauthenticated`.
9. **Logout.** `POST /auth/logout` returns 204, deletes the session row and clears the cookie. With no cookie it still returns 204. After logout the old cookie gets 401 on `/auth/me`.
10. **Role check.** `require_roles(...)` returns the current user. No session: 401. Logged in without a listed role: 403 `forbidden`. A user with two roles passes if either is listed. `clinic_admin` has no automatic access: a route must list it.
11. **Deny by default.** A test walks every route in the app and fails if a route is neither marked `@public` nor protected by `require_roles`. The test is shown to catch an unmarked route.
12. **Clinic scope.** The clinic id for a request comes from the session, never from the request body, path or query. `scoped_select(model, clinic_id)` adds the clinic filter. With two clinics in the database, a `UserRepository` for clinic A lists only A's users and returns nothing for B's user id.
13. **Session settings.** `SESSION_TTL_HOURS` (default 12, positive integer) and `COOKIE_SECURE` (default true) load from the environment. Bad values stop startup and name the variable.
14. **Create a user.** `make create-user` creates the clinic if it does not exist and one user with chosen roles. The password comes from a prompt or an environment variable, never a command argument. The service behind it rejects an unknown role and a duplicate email.
15. **Contract and docs.** `openapi.json` and `schema.d.ts` are regenerated. `make check` passes. README and `.env.example` gain the new settings and the create-user step. PRODUCT.md records the decisions.

## Changes

- Data (all new, ids are UUIDs, `created_at` on each):
  - `clinic`: `id`, `name`. This is the tenant root, so it has no `clinic_id`.
  - `app_user`: `id`, `clinic_id` FK, `email`, `full_name`, `password_hash`, `is_active`. Unique index on `lower(email)`. Unique `(clinic_id, id)` so child tables can reference it. (`user` is a reserved word in PostgreSQL.)
  - `user_role`: `clinic_id`, `user_id`, `role`. Primary key `(user_id, role)`. Composite FK `(clinic_id, user_id)` to `app_user`, so a role row cannot point at another clinic's user. Check on `role`.
  - `auth_session`: `id`, `clinic_id`, `user_id` (same composite FK), `token_hash` unique, `expires_at`. Index on `user_id`.
- API:

  | Route | Access | Result |
  | --- | --- | --- |
  | `POST /auth/login` | public | 200 user summary + cookie, 401, 422 |
  | `POST /auth/logout` | public (returns no data) | 204 |
  | `GET /auth/me` | any of the four roles | 200 user summary, 401 |

  `errors.py` gains fixed messages for 401 and 403. Error bodies stay on the one shape.
- UI: none. The login page comes in S0.5 (see decisions).
- Migrations: one additive revision `0002`. Nothing existing changes.
- Code, in the existing layers:
  - `models/` (`clinic.py`, `app_user.py`, `user_role.py`, `auth_session.py`, and a `ClinicScoped` mixin with `clinic_id`, FK and index).
  - `repositories/` (`user_repository.py`, `session_repository.py`). Every method takes `clinic_id`, with one named exception: `find_for_login(email)`, because the clinic is not known before login.
  - `services/auth_service.py` (login, logout, resolve session), `services/provisioning_service.py` (create clinic, create user).
  - `core/security.py` (hash and verify password, new token, hash token), `core/tenancy.py` (`scoped_select`), `core/access.py` (adds `require_roles`), `api/auth.py`, `api/deps.py` (`current_user`).
  - `scripts/create_user.py` (thin, calls the provisioning service). Makefile: `create-user`.
  - `core/config.py`: `session_ttl_hours`, `cookie_secure`.

## Decisions and risks

New dependency needs your approval (AGENTS.md stop): **`argon2-cffi`**. It is the standard Argon2 library and is small. Alternative: `hashlib.scrypt` from the standard library, no dependency, but we would own the hash format and parameters. I recommend `argon2-cffi`.

Your calls, to be recorded in PRODUCT.md on approval:

- **Cookie session or JWT: cookie session, stored in the database (recommended).** An opaque random token in an httpOnly cookie, with only its hash in `auth_session`. Tradeoff: one indexed lookup per request, in return for logout and deactivation that work instantly and no token in browser storage. JWT would need a revocation list to match that.
- **Browser access: Next rewrite, not CORS (recommended).** The web app proxies `/api/*` to the API, so the browser sees one origin, the cookie is first-party, and no CORS or `credentials` setup exists. Server components forward the cookie. The API keeps its routes without a prefix. Built in S0.5.
- **Roles in a table, as text with a check constraint (recommended).** Not a PostgreSQL enum: changing an enum later is a harder migration. Tradeoff: the list of roles lives in a check and in code, so both must change together.
- **No automatic admin power.** `clinic_admin` passes only where listed. The spec says permissions should be explicit. Tradeoff: every route lists its roles, slightly longer.
- **Login email lookup is not clinic-scoped.** Email is unique across clinics and the login form has no clinic picker. This is the one deliberate exception to "every query is scoped", marked by its name `find_for_login`.
- **CSRF: SameSite=Lax only, no token.** Lax blocks cross-site POSTs with the cookie, and the rewrite keeps everything same-origin. Gaps: no Origin check and no rate limiting. Fine for synthetic data. Revisit before any real patient data (the DPDP item stays open).
- **Where the login page goes: S0.5.** Then S0.5 becomes "login page, rewrite, one authenticated screen". I would update its line in ROADMAP.md after you agree, and keep it small.

Risks:

- **Size.** Four tables, three routes, a role dependency, a scoping helper, and a script. If the review feels too big, split: S0.4a models, migration, scoping helper, create-user; S0.4b login, session, roles, `/auth/me`. I recommend keeping it as one, because the scoping and role tests only mean something with real sessions.
- **Timing equalization** is best effort (hash a dummy value). It reduces, not removes, email enumeration.
- **`Secure` cookie** defaults to true. Over plain `http://localhost` some browsers (Safari) drop it, so `.env.example` sets `COOKIE_SECURE=false` for local work.
- **Branch base.** S0.3 is not merged and `.shipit/open.md` still asks for green CI on its PR. This slice regenerates S0.3's `openapi.json` and `schema.d.ts`, so it should branch from `main` after S0.3 is merged. The repo is currently on `slice/S0.3-web-skeleton`.

### Decisions made

- **401 stays `unauthenticated` for a bad login and a missing session.** The brief asked for `invalid_credentials` on login. One code per status is the S0.2 rule, and a separate code would need new machinery that can leak submitted values. The message is the same in both cases, so nothing is given away.
- **A duplicate email is caught by the database, not by a lookup first.** A lookup before insert cannot see rows another transaction has not committed yet. The unique index is the real guard, and the service turns that failure into `DuplicateEmailError`.
- **Three queries are not clinic-scoped, each named for why.** `find_for_login` (the clinic is unknown), `find_by_token_hash` and `delete_by_token_hash` (the cookie carries no clinic, and the hash is unique). The brief named only the first.
- **`/auth/me` lists all four roles** rather than a special "any signed-in user" bypass, so the route-walk test has one rule.
- **The test database is created per test, not per run.** The old fixture was session-scoped and built before `DATABASE_URL` was set, so every test shared one database and saw each other's rows.
- **`Secure` defaults to true in code and false in `.env.example`.** I added the two lines to the local `.env`, which is gitignored.

### Unsure points

- Logout's cleared cookie does not repeat `HttpOnly`. Starlette's `delete_cookie` only sends an expiry. Browsers still remove it, and the test checks the session row is gone.
- `get_or_create_clinic` matches on the clinic name and the name is not unique. Two clinics with the same name are possible. Fine for one clinic.
- The timing equalization is a fixed dummy hash, so it only roughly matches a real check.
