# S1.3 Book appointment

Status: done
Branch: slice/S1.3-book-appointment
Size: M (split option under Risks)
Actual time: not recorded.

## Goal

A receptionist can pick a patient, an appointment type, a clinician and a free time inside clinic hours, and book it. The database refuses to give one clinician two overlapping appointments.

## Acceptance criteria

1. **Schema.** `alembic upgrade head` adds `appointment`. `downgrade` to `0005` removes it. Upgrade, downgrade, upgrade works.
2. **Database overlap rule.** Inserting two rows for the same clinic and clinician whose times overlap fails with an exclusion violation, even when the service is bypassed. Back-to-back (one ends 10:00, next starts 10:00) is allowed. A `cancelled` or `no_show` row does not block. Different clinicians may overlap. `ends_at <= starts_at` fails a check.
3. **Clinicians.** `GET /clinicians` returns the active users in the session clinic who hold the `clinician` role (`id`, `full_name`), sorted by name. Inactive users, other roles and other clinics are left out.
4. **Availability.** `GET /appointments/availability?date=&clinician_id=&appointment_type_id=` returns the free start times for that clinic-local date. Slots start every 15 minutes from each working-hours interval's opening time. A slot appears only if the whole appointment fits inside one interval, does not overlap the clinician's blocking appointments, and starts after "now" in clinic time. Duration is the type's duration, or the clinic default when the type has none. A closed day returns `is_open: false` and no slots.
5. **Availability input.** An unknown or other-clinic clinician or type, an inactive type, a user who is not a clinician, or a date before clinic-today or more than 365 days ahead returns 422 naming the field.
6. **Book.** `POST /appointments` with `patient_id`, `clinician_id`, `appointment_type_id` and `starts_at` (timezone-aware) creates a `scheduled` appointment. `ends_at` is `starts_at` plus the duration. It returns 201 with the appointment. Extra fields return 422.
7. **Booking rules.** The service accepts only a start that availability would offer for that date, clinician and type. Otherwise 422: naive `starts_at`, past, beyond 365 days, outside hours, not on the 15-minute grid, patient unknown or `inactive`, clinician or type invalid as in 5. Errors name the field and never echo the value.
8. **Taken slot.** If the clinician already has an overlapping blocking appointment, `POST` returns 409 `slot_taken`. Two concurrent bookings of the same slot give one 201 and one 409 (the constraint decides, not the pre-check).
9. **Patient double booking.** If the patient already has an overlapping blocking appointment with any clinician, `POST` returns 409 `patient_busy`. This is a service check only (see Decisions).
10. **Upcoming.** `GET /patients/{id}/appointments` returns the patient's blocking appointments that end after now, soonest first, at most 20. Each has `id`, `starts_at`, `ends_at`, `status`, `clinician {id, full_name}`, `appointment_type {id, name}`. Unknown or other-clinic patient returns 404.
11. **Times on the wire.** `starts_at` and `ends_at` in every response are ISO 8601 in the clinic's offset (`2026-10-12T09:15:00+05:30`), so the web shows wall time without timezone maths.
12. **Audit.** A booking writes one `audit_event` in the same transaction: `entity_type` `appointment`, `action` `create`, `changed_fields` `[]`. No patient values. If the audit write fails, nothing is saved. A rejected booking writes nothing.
13. **Roles.** All four routes allow `receptionist`, `clinician`, `clinic_admin`. `inventory_admin` gets 403. No session gets 401.
14. **Tenancy.** With two clinics, clinic A cannot book B's patient, clinician or type, cannot see B's availability or upcoming list, and B's appointments do not block A's slots. The clinic id comes from the session.
15. **Contract and checks.** The route-walk test passes. `openapi.json` and `schema.d.ts` are regenerated. `make check` and `make web-build` pass.
16. **Book page.** `/patients/[id]/book` shows type, clinician and date (default clinic-today). Changing any of them loads the free times. Times show as buttons ("09:15"). States: "The clinic is closed on this day.", "No free times on this day.", "No clinicians are set up.", "You do not have access.", "Patient not found", "This patient is inactive." (no form) and a generic error. Choosing a time and pressing "Book" sends one request even on double click. On 409 it shows "That time was just taken. Pick another." and reloads the times. On success it goes to the patient page and shows "Booked."
17. **Patient page.** The detail page shows an "Upcoming appointments" section (date, time, type, clinician) or "No upcoming appointments." A "Book appointment" link appears for an active patient and a role that may book.

## Changes

- Data: new table `appointment` (migration `0006`, additive, reuses `btree_gist` from `0003`):
  - `id` uuid PK, `clinic_id`, `created_at` (the `ClinicScoped` mixin).
  - `patient_id` with FK `(patient_id, clinic_id)` to `patient (id, clinic_id)`.
  - `clinician_user_id` with FK `(clinic_id, clinician_user_id)` to `app_user (clinic_id, id)`.
  - `appointment_type_id` with FK `(appointment_type_id, clinic_id)` to `appointment_type (id, clinic_id)`.
  - `starts_at`, `ends_at` timestamptz. Check `ends_at > starts_at`.
  - `status` text, default `scheduled`, check in `scheduled`, `arrived`, `in_progress`, `completed`, `cancelled`, `no_show`. Only `scheduled` is written in this slice.
  - Exclusion `USING gist (clinic_id =, clinician_user_id =, tstzrange(starts_at, ends_at, '[)') &&) WHERE status NOT IN ('cancelled', 'no_show')`.
  - Indexes `(clinic_id, patient_id, starts_at)` and `(clinic_id, starts_at)` (the second is for S1.4's calendar, cheap now).
  - The composite FKs use unique keys that already exist. No change to existing tables.
- API (`clinic_id` from the session):

  | Route | Roles | Result |
  | --- | --- | --- |
  | `GET /clinicians` | `receptionist`, `clinician`, `clinic_admin` | 200, 401, 403 |
  | `GET /appointments/availability` | same | 200, 401, 403, 422 |
  | `POST /appointments` | same | 201, 401, 403, 409, 422 |
  | `GET /patients/{id}/appointments` | same | 200, 401, 403, 404, 422 |

  Availability response: `{date, timezone, is_open, duration_minutes, slots: [{starts_at, ends_at}]}`.
- Code, in the existing layers:
  - `domain/appointment.py`: statuses, blocking statuses, `APPOINTMENT_ROLES`, slot step and horizon, and a pure function that turns intervals, busy spans, duration, date, timezone and now into free slots. Booking reuses it.
  - `repositories/appointment_repository.py`: add, busy spans for a clinician or patient on a span, upcoming for a patient. All scoped by clinic.
  - `repositories/user_repository.py`: `list_clinicians` and `get_clinician`.
  - `services/appointment_service.py`: `list_clinicians`, `find_availability`, `book_appointment`, `list_upcoming`. Takes `now` so tests control the clock. Maps the exclusion violation (SQLSTATE `23P01`) to `SlotTakenError`.
  - `api/appointments.py` and `api/clinicians.py`: thin routes.
- UI: `apps/web/features/appointments/`: book screen (client component, fetches availability through `/api`), slot buttons, upcoming list. Page `app/(app)/patients/[id]/book/page.tsx` loads the patient, clinicians and types on the server. Native `<select>`, no new UI-kit component. The patient detail page gains the upcoming section and the book link. No new nav item.
- Migrations: additive only.

## Decisions and risks

Your calls (my recommendation first):

- **15-minute slot grid from each interval's opening time (recommended).** Predictable times like 09:00, 09:15. Booking accepts only grid times, so the API and the screen agree. Alternative: step by the type's duration. Fewer buttons but a 60-minute type could only start on the hour from opening, wasting gaps.
- **Cancelled and no-show do not block a slot (recommended).** Built into the constraint now so S1.4's cancel needs no migration. Alternative: only cancelled frees the slot. Changing the set later means a migration on this table.
- **Patient double booking is a service check, not a constraint (recommended).** One patient in two chairs at once is a mistake worth catching, but a second exclusion constraint is more than the roadmap asks. Tradeoff: two simultaneous bookings for one patient with different clinicians could both pass. Alternative: skip the check entirely, or add the second constraint.
- **Duration is fixed by the type or clinic default, no per-booking override.** Keeps booking to four fields. Override can come with reschedule in S1.4 if the desk asks.
- **No notes field yet.** Free text on an appointment invites clinical detail and is not needed for the core loop. Add it with a reason later.
- **Same three roles book as register patients.** `inventory_admin` cannot. Alternative: clinicians cannot book, only view.
- **`GET /clinicians` is a new, narrow read of staff names.** S0.5 said "no staff list"; this is only id and name for users holding `clinician`, needed to assign one. It is not an auth or role-check change.
- **Horizon 365 days.** Stops typo years. Alternative: no limit.

Risks:

- Timezones. Slots are built in clinic-local wall time and converted with `zoneinfo`. A local time that does not exist on a DST change day is skipped. `Asia/Kolkata` has no DST, so one test uses `Europe/London` on a change day.
- The concurrency test needs two real database sessions. Same pattern as the patient-number counter test.
- Size. Seventeen criteria, about the same as S1.2. If it is too big, split it: S1.3 is criteria 1 to 15 (API) and S1.3b is the book page and patient-page section (16 and 17). I will ask before splitting.
- Branch base: `origin/main` after S1.2's merge (PR #12).

### Decisions made

- A start is accepted when it would be offered if the clinician were free. A clinician clash is left to the exclusion constraint, so two concurrent bookings return one success and one `slot_taken`.
- If the same patient is already in that span, the service returns `patient_busy` before insert. When both rules could apply, `patient_busy` wins.
- Create and the upcoming list share one appointment shape, and it includes `patient_id`.
- 409 messages are fixed: "That time was just taken." and "That patient already has an appointment then." The screen shows "That time was just taken. Pick another." for either code.
- The page's generic error is "Something went wrong." No appointment types shows "No appointment types are set up."
- A grid time that does not fit the duration is `outside_hours`. A time inside the hours but off the grid is `not_on_grid`. A time earlier than now is `past`.
- An ambiguous clock on a daylight-saving fallback is offered once, at the earlier offset. A skipped clock is left out.
- The patient-schema test now expects head `0006_appointments`, because upgrade head includes this table.

### Unsure points

- The upcoming list includes `patient_id`, which the brief did not name. Say if you want it off that response.
- Same patient and same clinician returns `patient_busy`, not `slot_taken`.
