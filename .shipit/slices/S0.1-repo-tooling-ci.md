Status: built

## Goal

Anyone can clone the repo, run one command per app to lint, type check and test it, start
PostgreSQL with Docker Compose, and see the same checks pass in CI.

## Acceptance criteria

1. `apps/api` is a Python project with a pinned Python version. `uv sync` installs it from
   a lockfile.
2. In `apps/api`, `ruff check`, `ruff format --check`, `mypy` (strict) and `pytest` all pass.
   There is one placeholder test so the runner proves it works.
3. `apps/web` is a TypeScript project. `pnpm lint`, `pnpm typecheck` and `pnpm test` all
   pass. There is one placeholder test. It is not a Next.js app yet (that is S0.3).
4. `docker compose up -d db` starts PostgreSQL. The container reports healthy. Data is kept
   in a named volume.
5. A smoke test connects to the database using `DATABASE_URL` and runs `SELECT 1`. It is
   skipped when `DATABASE_URL` is not set, so the other checks do not need Docker.
6. `.env.example` lists every variable the repo reads. `.env` stays ignored by git. No
   secrets are committed.
7. A root `Makefile` has `lint`, `typecheck`, `test`, `check` (all three), `db-up` and
   `db-down`. `make check` runs every check for both apps.
8. A GitHub Actions workflow runs on pull requests and on pushes to `main`. It runs the
   API checks (with a PostgreSQL service container, so the smoke test runs) and the web
   checks. Both jobs fail when any check fails.
9. The root README explains setup in under ten steps: prerequisites, clone, `.env`, database,
   `make check`.

## Decisions and risks

New dependencies need your approval (AGENTS.md stop). Proposed list:

- API dev tools: `uv` (package manager, already installed here), `ruff`, `mypy`, `pytest`,
  and `psycopg` (only for the smoke test; S0.2 picks the real driver with SQLAlchemy).
- Web dev tools: `pnpm`, `typescript`, `eslint` (with `typescript-eslint`), `vitest`.
- Services: PostgreSQL 16 image `postgres:16`. No new external account. GitHub Actions
  is used because the remote is on GitHub.

Choices where I recommend one option:

- **Python version: 3.12.** The system Python here is 3.9, which is too old for current
  FastAPI and typing features. `uv` installs and pins 3.12 without touching the system one.
- **Async driver:** the FastAPI rules mention asyncpg. I will not pick it here. `psycopg`
  works for both sync and async and is enough for the smoke test. S0.2 decides the driver
  when SQLAlchemy is added.
- **Web tooling before Next.js exists.** The roadmap puts Next.js in S0.3, but CI for the
  web app is in S0.1. I recommend a small TypeScript package with ESLint and Vitest now, and
  S0.3 builds the Next.js app on top of it. Tradeoff: S0.3 may adjust the ESLint config to
  fit Next.js, and the test runner choice (Vitest or Jest) is fixed here. The alternative
  is to do API checks only in S0.1 and add web checks in S0.3, which keeps S0.1 smaller but
  leaves CI half done. Tell me if you prefer that.
- **Docker is not installed on this machine** (`docker` command not found). I cannot run
  criterion 4 locally. I can verify the Compose file with static checks and in CI, but you
  will need Docker Desktop (or Colima) to do the click-through. If you would rather not
  install Docker, say so and we revisit the PostgreSQL decision in PRODUCT.md.
- **Git state:** `main` has uncommitted changes (PRODUCT.md, ROADMAP.md, moved files under
  `.claude/` and `docs/`). Commit or stash those before I create the slice branch, so the
  slice diff shows only S0.1.

### Decisions made

- ESLint 10, not 9. The 9.39 line is unsupported, and `typescript-eslint` 8 allows ESLint 10.
- `psycopg[binary]` so install does not need PostgreSQL headers. Still the `psycopg` package.
- Hatchling is the build backend, which is what `uv` expects for an installable package.
- CI uses Node 24. `package.json` allows Node 22 or newer, matching this machine's Node 24.
- Action pins: `actions/checkout@v5`, `astral-sh/setup-uv@v10.0.1`, `pnpm/action-setup@v6.0.10` with pnpm `10.15.1`, `actions/setup-node@v4`.
- Local database user, password and database name are all `dentacircle`. That is a local default, written in `.env.example` and Compose, not a production secret.
- `pnpm.onlyBuiltDependencies` includes `esbuild` so Vitest can build its binary on a clean CI install.

### Unsure points

- Docker is not installed here, so the container was never started and the smoke test never saw a real database. With `DATABASE_URL` unset, pytest skips it. With a closed port, the same test fails on connection refused, so it does try to connect.
- CI has not run. It will run on the pull request.
- `connect_timeout=5` is extra insurance so a dead database fails in five seconds. The brief did not mention a timeout.

### Click-through

1. Install Docker if it is not installed.
2. From the repo root: `cp .env.example .env`
3. `make db-up`
4. `docker compose ps` and confirm `db` is healthy.
5. `set -a && source .env && set +a && make check`
6. Confirm the API run says the smoke test passed, not skipped.
7. `make db-down`
